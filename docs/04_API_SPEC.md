# 04 — API Specification (v1)

Base URL: `/api/v1`. JSON only (except file upload). OpenAPI is generated by FastAPI and committed as
`backend/openapi.json`; the dashboard client is generated from it (`openapi-typescript`).

## 1. Conventions

| Topic | Rule |
|---|---|
| Auth | Session cookie (`__Host-pfa_session`, HttpOnly, Secure, SameSite=Strict) holding a short-lived JWT (15 min) + rotating refresh token (8 h idle, 12 h absolute). CSRF: double-submit token header `X-CSRF-Token` on mutating requests. |
| Tenant | Derived from the user; never accepted from request body. Super-admin may pass `X-Account-Id` (audited). |
| IDs | Prefixed strings (`case_01H…`). |
| Time | ISO-8601 UTC in payloads; UI converts. |
| Pagination | Cursor: `?limit=50&cursor=…` → `{ "data": [...], "next_cursor": "…" }`. Max limit 200. |
| Filtering | Query params, e.g. `?status=open,acknowledged&priority=p1`. |
| Read/list with a complex body | HTTP `QUERY` (RFC 10008) — see ADR 0005 — for search/list/filter endpoints whose filters don't fit cleanly in query params (date ranges, multi-field filters, account scoping). Simple filters stay on `GET` + query params. Never for anything that creates/updates/deletes. |
| Idempotency | `Idempotency-Key` header required on POST that creates resources or triggers actions; stored 24 h. |
| Concurrency | Case mutations require `If-Match: <version>`; mismatch → 409 `PFA-CASE-409`. |
| Rate limit | 60 req/min/user default, 5/min for login, 10/min for uploads. 429 with `Retry-After`. |
| Errors | Always the envelope below. |

### Error envelope
```json
{
  "error": {
    "code": "PFA-CASE-004",
    "message": "A resolution note is required to close a case.",
    "details": {"field": "resolution_note"},
    "request_id": "req_01J…"
  }
}
```
HTTP status mapping: validation 422, auth 401, permission 403, not found 404 (also used for other-tenant
resources — never 403, to avoid existence leaks), conflict 409, rate limit 429, dependency failure 503,
unexpected 500. Full code list: doc 06.

## 2. Auth

| Method | Path | Body / Notes | Roles |
|---|---|---|---|
| POST | `/auth/login` | `{email, password}` → sets cookies; if MFA enabled returns `{mfa_required: true, mfa_token}` | public |
| POST | `/auth/mfa/verify` | `{mfa_token, code}` | public |
| POST | `/auth/refresh` | rotates refresh token | cookie |
| POST | `/auth/logout` | revokes refresh token | any |
| POST | `/auth/password/forgot` | `{email}` → always 202 (no enumeration) | public |
| POST | `/auth/password/reset` | `{token, new_password}` | public |
| GET | `/me` | current user, role, account, permissions list | any |

Lockout: 5 failed logins → 15 min lock (`PFA-AUTH-003`). MFA (TOTP) mandatory for `admin`,
`super_admin`; optional for others in MVP.

### CSV contract
Header row required, case-insensitive, extra columns ignored (warned).

| Column | Req | Validation | Error code |
|---|---|---|---|
| `external_patient_id` | ✅ | 1–64 chars, `[A-Za-z0-9._-]` | PFA-ING-010 |
| `phone` | ✅ | normalise to E.164 (+91 default); 10-digit Indian mobile starting 6–9, or permitted landline | PFA-ING-011 |
| `visit_date` | ✅ | `YYYY-MM-DD` or `DD-MM-YYYY` (account setting); not in future | PFA-ING-012 |
| `visit_type` | ✅ | outpatient \| diagnostic (synonyms: OPD, OP, lab, radiology mapped) | PFA-ING-013 |
| `department` | ✅ | maps to `departments.code`; unknown → auto-created as `unmapped_<code>` + warning | PFA-ING-014 (warn) |
| `doctor_name` | ⚠️ | ≤ 80 chars | — |
| `preferred_language` | ⚠️ | ISO 639-1 in account languages; else ignored + warning | PFA-ING-015 (warn) |
| `patient_age` | ✅ | integer 0–130 | PFA-ING-016 |
| `consent_flag` | ⚠️ | true/false/yes/no/1/0 | PFA-ING-017 |
| `location_id` | ✅ | matches `locations.external_location_id` | PFA-ING-018 |

Batch rejected entirely if: header missing required column (`PFA-ING-002`), > 30% rows invalid
(`PFA-ING-003`, configurable), encoding not UTF-8 (`PFA-ING-004`), file > limits (`PFA-ING-005`),
same SHA-256 already ingested (`PFA-ING-006`). CSV injection guard: cells beginning with `= + - @`
are stored with a leading `'` when exported.

## 7. Cases

| Method | Path | Body | Roles |
|---|---|---|---|
| GET | `/cases` | filters: status, priority, dept, owner=`me`, sla=`breached\|due_soon`, q | quality, admin, dept_owner (scoped), read_only |
| GET | `/cases/{id}` | case, complaint (verbatim decrypted — audited), events, call link | same |
| POST | `/cases/{id}/acknowledge` | `{note?}` | quality, dept_owner, admin |
| POST | `/cases/{id}/assign` | `{assignee_user_id, note?}` | quality, admin |
| POST | `/cases/{id}/start` | → in_progress | assignee, quality |
| POST | `/cases/{id}/notes` | `{note}` (≤ 4000 chars) | assignee, quality, admin |
| POST | `/cases/{id}/resolve` | `{resolution_note (≥ 20 chars), patient_contacted: bool}` | assignee, quality |
| POST | `/cases/{id}/close` | `{note?}` (requires resolved) | quality, admin |
| POST | `/cases/{id}/reopen` | `{reason}` | quality, admin |
| POST | `/cases/{id}/merge` | `{into_case_id, note}` | quality |
| POST | `/cases/{id}/invalidate` | `{reason}` — cannot invalidate p1 without a second quality user confirming (`PFA-CASE-007`) | quality |
| POST | `/cases` | manual case from a call: `{call_id, reason_codes, priority, summary}` | quality |

Allowed transitions (enforced by `domain/case_lifecycle.py`):

```
open        → acknowledged | assigned | merged | invalid
acknowledged→ assigned | in_progress | merged | invalid
assigned    → acknowledged | in_progress | resolved | merged
in_progress → resolved | assigned
resolved    → closed | reopened
closed      → reopened
reopened    → acknowledged | assigned | in_progress
merged, invalid → (terminal)
```
Acknowledging stops the ack SLA timer; `assign` from `open` also sets `acknowledged_at` if the assigner
is quality (acknowledge-by-assignment).

Common params: `from`, `to` (≤ 366 days), `location_id`, `department_id`, `granularity=day|week|month`.

## 10. Webhooks — inbound (telephony)

| Path | Purpose |
|---|---|
| `POST /webhooks/plivo/answer/{call_id}` | Returns XML to bridge call to LiveKit SIP room |
| `POST /webhooks/plivo/status/{call_id}` | ringing / answered / completed / busy / no-answer / failed, duration, billed |
| `POST /webhooks/plivo/machine/{call_id}` | AMD result |

Rules: verify Plivo signature (`X-Plivo-Signature-V3` + nonce) → reject 401 `PFA-WH-001`; dedupe by
`(provider_call_id, event, timestamp)`; process idempotently; respond < 2 s (heavy work to Celery);
unknown `call_id` → 200 + log warning (avoid provider retries storms).

## 11. Webhooks — outbound (Phase 2, schema frozen now)

Event types: `case.created`, `case.status_changed`, `case.sla_breached`, `call.completed`.
Signed with HMAC-SHA256 header `X-PFA-Signature: t=<ts>,v1=<hex>`. Retries: 1 min, 5 min, 30 min,
2 h, 6 h then dead-letter. Payloads never include verbatims or phone numbers — only IDs + links.

## 12. Health
